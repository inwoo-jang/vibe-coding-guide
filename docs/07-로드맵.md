### 3. GitHub + Vercel 배포

**`vercel.json` 이 하는 일 (JSON에는 주석을 못 달아서 여기 적는다)**

```json
{ "rewrites": [{ "source": "/((?!api/).*)", "destination": "/index.html" }] }
```

`/projects` 같은 주소를 브라우저에 직접 치거나 그 페이지에서 **새로고침하면 404**가 난다.
Vercel 이 `/projects` 라는 파일을 찾다가 없어서 그렇다. 실제 주소 판단은 브라우저 안의
react-router 가 하므로, 파일이 없는 요청은 전부 `index.html` 로 넘겨야 한다.
`(?!api/)` 는 "`/api` 로 시작하는 건 빼고"라는 뜻 — 그건 서버 함수라 넘기면 안 된다.

**이걸 빼먹으면 첫 화면은 되는데 새로고침만 하면 404가 난다.** 배포 후 반드시
`/projects` 에서 새로고침해서 확인할 것.


- [ ] 원격 저장소 생성, 푸시
- [ ] `.env.local` 이 커밋에 안 들어갔는지 확인 (`git log -p | grep -i 'sk-\|supabase'`)
- [ ] Vercel 연결, 환경변수 등록 — `.env.example` 의 이름 그대로
- [ ] `OPENAI_API_KEY` 는 **VITE_ 없이** 넣는다. 붙이면 배포 빌드가 중단된다 (의도된 동작)
- [ ] Supabase Auth 의 Site URL / Redirect URL 에 배포 주소 추가 —
      **이걸 빼면 매직 링크가 localhost 로 간다**
- [ ] 배포된 번들에 키가 없는지 확인 → [09-보안-키관리.md](09-보안-키관리.md)

## 작업할 때 지킬 것

- **`lib/` 훅 경계를 깨지 않는다** — 화면에서 `supabase` 나 `fetch('/api/ai')` 를
  직접 부르지 않는다 (D-006, D-012)
- **AI 호출을 `useEffect` 에 넣지 않는다** — 새로고침마다 돈이 나간다 (D-013).
  새 AI 기능은 [08-AI기능.md](08-AI기능.md)의 체크리스트를 따른다
- **콘텐츠는 `src/data/chapters.js` 만 고친다** (D-005)
- **`chapters.js` 의 `id` 를 바꾸지 않는다** — 저장된 진도가 끊긴다
- **하드코딩된 색을 새로 쓰지 않는다** — `src/index.css` 의 `:root` 변수를 쓴다
- **`.env.local` 을 커밋하지 않는다** — 빌드 검사가 막지만, 막히기 전에 안 하는 게 낫다
