# PRD — 바이브코딩 가이드

작성 2026-08-03 · 상태: v1 개발 중

## 한 문장

코딩을 한 번도 안 해본 사람이 **AI에게 무엇을 어떻게 말해야 하는지**를 기획부터 배포까지 8단계로 따라 배우는 웹.

## 왜 만드나

주변에 "AI 있으니까 나도 앱 만들 수 있지 않아?"라고 묻는 친구가 몇 명 있다.
막상 시작하면 대부분 같은 곳에서 무너진다.

1. 무엇을 만들지 정하지 못한 채 AI에게 "앱 만들어줘"라고 한다
2. 코드가 나오긴 하는데 에러가 나면 그 에러를 어떻게 전달할지 모른다
3. 되돌리는 법을 몰라서, 한 번 꼬이면 처음부터 다시 한다
4. 어찌어찌 굴러가는데 API 키가 코드에 박혀 있다

기존 코딩 강의는 문법부터 가르치고, 바이브코딩 콘텐츠는 "이렇게 하면 5분 만에 됩니다" 데모에서 끝난다.
**그 사이 — 순서와 말하는 법 — 를 다루는 자료가 없다.**

## 대상 사용자

**주 사용자: 코딩 경험이 없는 내 친구 (2~3명).**

- 컴퓨터는 쓸 줄 알지만 터미널은 처음 연다
- 만들고 싶은 게 이미 하나쯤 있다 (모임 정산, 취미 기록 같은 것)
- 혼자 검색하며 헤매다 포기한 경험이 있다
- 한국어로 읽는다

**대상이 아닌 사람:** 이미 코드를 쓸 줄 아는 개발자, 팀 단위 도입 검토자.
이들을 대상에 넣는 순간 문장이 어려워지고 분량이 늘어난다. 명시적으로 뺀다.

## 이 가이드가 하는 약속

> 순서대로 따라오면, 당신의 아이디어 하나가 인터넷에 올라간 웹사이트가 된다.
> 그 과정에서 막혔을 때 빠져나오는 법도 같이 배운다.

## 하지 않는 약속

- 문법을 가르치지 않는다 (변수, 반복문, 함수 문법 설명 없음)
- "코딩 없이" 라고 말하지 않는다. 코드는 읽어야 한다. 다만 처음부터 쓰지는 않는다
- 특정 AI 도구의 최신 기능 추적을 하지 않는다. 도구는 바뀌어도 순서는 안 바뀐다

## 성공 기준

| | 지표 | 목표 |
|---|---|---|
| 1차 | 친구 중 **끝까지 따라와서 실제로 배포까지 한 사람** | 3명 중 1명 이상 |
| 2차 | 커리큘럼 완주율 (진도 8/8) | 방문자의 20% |
| 3차 | "이 챕터 무슨 말인지 모르겠다"는 피드백을 받은 챕터 | 0개가 목표, 받으면 그 챕터를 고친다 |

친구 3명이 대상이므로 지금은 숫자보다 **직접 물어보는 피드백**이 진짜 지표다.
로그 기반 측정은 사용자가 늘었을 때 켠다 → [05-이벤트-로그.md](05-이벤트-로그.md)

## 핵심 원칙 (콘텐츠를 쓸 때 지킬 것)

1. **모든 챕터에 그대로 복사해 쓸 프롬프트가 있다.** 설명만 있고 프롬프트가 없는 챕터는 미완성이다.
2. **프롬프트는 그 단계 안에 둔다.** 기획 프롬프트와 디버깅 프롬프트는 성격이 달라서, 한곳에 모아두면 아무도 안 쓴다. `/prompts`는 모아 보기용 색인일 뿐이다.
3. **이 사이트 자체가 예제다.** 가이드에서 "RLS를 켜라"고 하면 이 저장소도 RLS가 켜져 있어야 한다. 말과 코드가 어긋나면 코드를 고친다.
4. **한 챕터는 한 번에 앉아서 끝낼 수 있어야 한다** (20~60분).
