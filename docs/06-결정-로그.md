# 결정 로그

내린 결정과 **그 이유**를 시간순으로 쌓는다.

규칙:

- **지난 항목을 고치지 않는다.** 생각이 바뀌면 새 항목을 쓰고 옛 항목 아래에 `→ D-00N으로 대체됨`만 붙인다
- 여기 있는 항목은 **다시 논쟁하지 않는다.** 다시 논쟁하려면 새 사실이 있어야 하고, 그럼 새 항목이 된다
- AI에게 작업을 시킬 때 이 파일을 붙여넣으면, 이미 끝난 논의를 다시 꺼내지 않는다

### D-001 · 프레임워크는 React + Vite (2026-08-03)

**대안:** Vue, 바닐라 HTML/JS, Next.js

**결정:** React + Vite

**이유:** 처음엔 정적인 읽기 전용 사이트라 바닐라로 충분해 보였다. 그런데 로그인·진도 저장·관리자 화면이 들어오면서 문서가 아니라 **앱**이 됐다.
그리고 이 사이트를 AI 코딩 도구로 만들면서 그 과정을 가이드로 쓴다. **AI가 가장 정확한 코드를 뽑는 프레임워크를 고르는 것이 이 프로젝트에서는 기능 요구사항이다.** 학습 자료와 예제가 가장 많은 React가 그 기준에서 앞선다.
Next.js는 서버 렌더링·라우팅 규칙 등 초보에게 설명해야 할 개념이 두 배가 된다. SEO가 목표가 아니라 뺐다.

### D-002 · DB는 Supabase (Firebase 아님) (2026-08-03)

**대안:** Firebase, 서버 없이 localStorage만

**결정:** Supabase

**이유:** 가이드에 "테이블 설계"와 "RLS 보안" 챕터가 있다. **가르치는 것과 이 저장소의 실제 코드가 1:1로 맞아야** 예제로 쓸 수 있다.
Firebase는 NoSQL이라 "테이블/컬럼/관계"를 설명할 수 없고, 보안 규칙도 자체 문법이라 다른 데서 못 쓴다. SQL과 RLS는 어디 가도 쓰인다.
localStorage만 쓰면 "기기 바꾸면 사라짐"을 설명할 수는 있지만 DB 챕터가 통째로 비게 된다.

### D-003 · 커리큘럼을 3단계에서 8단계로 늘림 (2026-08-03)

**처음 안:** 기획 → 빌드 → DB/보안 (3단계)

**결정:** 준비 · 기획 · 설계 · 빌드 · 데이터 · 보안 · 배포 · 유지보수 (8단계)

**이유:** 3단계 안은 **초보가 실제로 무너지는 지점 세 곳**을 빼먹었다.
(1) 시작 전 — 도구를 못 고르고 첫 대화에서 뭘 말할지 몰라서 아예 시작을 못 한다
(2) 막혔을 때 — 되돌리는 법을 몰라 처음부터 다시 한다. 가장 흔한 포기 지점이다
(3) 배포 — 만들고 남에게 못 보여주면 완주한 느낌이 안 든다
이 셋은 "고급 내용"이 아니라 **없으면 완주가 안 되는 것**이라 뺄 수 없다.

### D-004 · 프롬프트는 챕터 안에 심는다 (2026-08-03)

**대안:** "프롬프트 모음" 챕터를 따로 만든다

**결정:** 각 챕터 안에 둔다. `/prompts`는 모아 보는 색인일 뿐이다

**이유:** 기획 프롬프트와 디버깅 프롬프트는 **쓰는 순간이 다르다.** 한곳에 모아두면 "필요할 때 거기까지 찾아가지 않는다."
프롬프트는 그 단계를 하고 있을 때 눈앞에 있어야 쓰인다.
`/prompts`는 이미 해본 사람이 다시 찾을 때를 위한 색인이지 콘텐츠 원본이 아니다. **원본은 언제나 `chapters.js`다.**

### D-005 · 콘텐츠는 `src/data/chapters.js` 한 파일 (2026-08-03)

**대안:** 챕터별 마크다운 파일, DB(CMS)

**결정:** JS 파일 하나. 객체 모양을 나중에 그대로 테이블 스키마로 쓴다

**이유:** 글을 고치는 사람이 나 혼자다. 파일 하나면 검색·일괄수정이 제일 빠르고, AI에게 통째로 붙여넣기도 쉽다.
마크다운으로 쪼개면 파서·로더가 필요해지고, 지금 얻는 게 없다.
대신 **`id`/`order`/`sections`/`prompts` 모양을 미리 테이블처럼 잡아뒀다.** CMS로 옮길 때 그대로 `create table` 하면 된다.

### D-006 · 저장 계층은 `lib/` 훅 뒤에 숨긴다 (2026-08-03)

**결정:** 화면 컴포넌트는 `localStorage`도 `supabase`도 직접 부르지 않는다. `useProgress()` / `useAuth()`만 쓴다

**이유:** 이 프로젝트는 **저장 방식이 바뀔 게 확정된 상태로 시작했다** (localStorage → Supabase).
경계를 미리 그어두면 교체가 한 파일 수정이고, 안 그어두면 화면 8개를 다 고쳐야 한다.
가이드의 "설계" 챕터에서 가르치는 내용이기도 하다. **이 경계를 깨지 말 것.**

### D-007 · 로그인은 이메일 매직 링크만 (2026-08-03)

**대안:** 비밀번호 로그인, 구글/깃허브 소셜 로그인

**결정:** 매직 링크(이메일로 오는 로그인 링크)

**이유:** 대상이 초보다. **비밀번호를 만들면 반드시 잊어버리고, 그 대응(재설정 메일, 문의)이 사용자 3명짜리 프로젝트엔 과하다.**
소셜 로그인은 OAuth 앱 등록·리다이렉트 설정이 필요한데 얻는 게 "클릭 한 번 덜 하기"뿐이다.
매직 링크는 비밀번호가 아예 없어서 유출될 것도 없다.

→ **D-016으로 대체됨.** AI 기능이 들어오면서 로그인이 편의가 아니라 요금 통제 장치가
되었고, 전제가 바뀌었다.

### D-010 · 진도를 프로젝트 단위로 바꿈 (2026-08-03)

**처음 안:** 챕터마다 완료 체크 (사용자당 하나의 진도)

**결정:** 사용자가 "프로젝트"를 만들고, 진도는 프로젝트에 매달린다. 여러 개 가능

**이유:** 챕터별 체크만 있으면 남는 기록이 "읽었다"가 된다.
이 가이드의 목적은 읽는 게 아니라 **아이디어 하나를 배포까지 실제로 끌고 가는 것**이다.
"03 빌드 완료"는 의미가 약하지만 "회비 관리 웹 — 03 빌드 완료"는 상태를 말해준다.
덤으로 AI 기능이 성립한다 — 프로젝트 정보가 있어야 프롬프트를 맞춰주고 점검표를 만들 수 있다.
두 번째 프로젝트를 만들 수 있게 한 것도 의도적이다. 한 사이클을 돌아본 사람이
다시 도는 게 이 가이드의 성공 모습이다.

**대가:** 진도 저장 구조가 한 겹 깊어졌고(`{projectId: {chapterId: ...}}`),
프로젝트가 없을 때의 화면을 모든 곳에서 처리해야 한다.
옛 기록(`vcg.progress.v1`)은 첫 프로젝트로 자동 이관해서 버리지 않았다.

### D-012 · AI 키는 서버리스 함수에만 둔다 (2026-08-03)

**대안:** 브라우저에서 OpenAI를 직접 호출 (`VITE_OPENAI_API_KEY`)

**결정:** `api/ai.js` 서버리스 함수를 두고, 브라우저는 그 함수만 부른다

**이유:** 브라우저에서 직접 부르면 키가 사이트 소스에 그대로 박힌다. 개발자 도구를
열면 누구나 가져가고, **내 카드로 남이 API를 쓴다.**
그리고 이 사이트는 보안 챕터에서 정확히 그러지 말라고 가르친다 —
말과 코드가 어긋나면 가이드가 거짓말이 된다.

**대가:** 서버 함수가 하나 생겼고, 원래는 로컬 테스트에 `vercel dev` 가 필요했다.
그건 `vite.config.js` 에 개발용 미들웨어를 넣어 없앴다 — `npm run dev` 하나로 돌아간다.
초보에게 명령어를 하나 더 외우게 하는 건 그 자체로 이탈 지점이다.

**덤:** 시스템 프롬프트도 서버에 남게 됐다. 브라우저 번들에 안 들어가고,
사용자가 바꿔서 조종할 수도 없다.

### D-013 · 요금 방어를 기능의 완료 조건에 포함 (2026-08-03)

**결정:** AI 기능은 아래 장치 없이는 "완성"으로 치지 않는다 → [08-AI기능.md](08-AI기능.md)

1. **자동 호출 경로를 만들지 않는다.** `useEffect` 안에서 AI를 부르는 코드는 금지.
   버튼 `onClick` 만 허용 (`AiPanel` 컴포넌트가 구조로 강제)
2. 같은 입력이면 캐시된 답을 준다. 캐시 사용 시 화면에 표시한다
3. 요청 중 재호출 차단 (단일 실행 + 버튼 잠금)
4. 작업마다 `maxTokens` 상한을 정한다. 입력도 4000자에서 자른다
5. 1분에 10회 넘으면 서버가 거절한다
6. 사용량을 화면에 보여준다

**이유:** AI 기능은 다른 기능과 달리 **버그가 곧 돈**이다.
가장 흔한 사고는 `useEffect` 안의 호출이다 — 새로고침·뒤로가기마다 요금이 나가고,
React StrictMode 는 개발 중 effect 를 두 번 돌려서 두 배로 나간다.
사고가 난 뒤에 알아채는 게 아니라 **애초에 그 경로가 없게** 만들었다.

"나중에 최적화"로 미루지 않은 이유: 나중에 하려면 이미 흩어진 호출을 전부 찾아야 한다.
처음부터 통로를 하나(`lib/ai.js`)로 두는 게 훨씬 싸다.

### D-015 · 커리큘럼을 웹/모바일웹/앱 트랙으로 나누지 않는다 (2026-08-03)

**검토한 안:** ① 웹 / 모바일웹 / 반응형 3개 트랙 ② 여기에 배포앱까지 4개 트랙

**결정:** 트랙을 나누지 않는다. **반응형 웹 하나**를 기본으로 두고,
배포 챕터에 "홈 화면에 추가(PWA)" 한 절과 "진짜 앱이 필요한 순간" 한 절을 넣는다

**이유 ①: 웹/모바일웹/반응형은 나란한 세 가지가 아니다.**
반응형은 웹과 모바일웹을 만드는 *방법*이지 세 번째 선택지가 아니다.
셋으로 나눠 가르치면 초보가 "모바일용을 따로 만들어야 하는구나"라고 잘못 배운다.
`m.naver.com` 식 별도 모바일 사이트는 업계가 이미 버린 방식이다.
**틀린 멘탈 모델을 심는 커리큘럼은 콘텐츠가 늘어나는 것보다 나쁘다.**

**이유 ②: 앱은 4번째 트랙이 아니라 다른 산이다.**
배포 장벽이 웹과 비교가 안 된다 — Apple 개발자 계정 연 $99, Google 최초 $25,
심사 며칠~2주, iOS는 Mac + Xcode 필수, 오타 하나 고쳐도 재심사.
터미널을 방금 배운 사람(D-016 참고: 준비 챕터에 터미널 설명을 넣어야 했던 수준)에게
6단계쯤에서 "개발자 계정을 결제하세요"는 완주가 끊기는 벽이다.
**완주율이 1차 성공 지표**([01-PRD.md](01-PRD.md))인데 트랙 분기는 완주율을 올리지
않으면서 콘텐츠를 3~4배로 만든다.

**대신 얻는 것:** PWA는 설정 파일 하나 + HTML 세 줄로 "폰 홈 화면에 내 아이콘"이
생긴다. 비용 0원, 심사 0일. 초보가 원하는 "앱 같은 성취감"의 대부분이 여기서 나온다.
그리고 이 사이트가 직접 그렇게 구현돼 있어서 살아있는 예제가 된다
(`public/manifest.webmanifest`, `index.html`).

**앱을 아예 안 다루는 건 아니다.** 배포 챕터에 "진짜 앱이 필요한 순간" 절을 두고
판단 기준(푸시·카메라·오프라인·스토어 검색)과 실제 비용을 적었다.
그리고 **지금 만든 웹이 버려지지 않는다**는 것도 명시했다 — 나중에 Capacitor 같은
도구로 감쌀 수 있다. 선택지를 닫는 게 아니라 순서를 정한 것이다.

**대가:** 앱을 만들고 싶어서 온 사람은 이 가이드에서 앱을 못 만든다.
그건 받아들인다 — 대상은 "만들고 싶은 게 하나 있는 코딩 무경험자"이지
앱 개발자 지망생이 아니다([01-PRD.md](01-PRD.md)).

### D-016 · 로그인은 구글 + 카카오 OAuth (매직 링크 대체) (2026-08-03)

**D-007을 대체함.** 그때는 이메일 매직 링크만 쓰기로 했었다.

**결정:** 구글·카카오 소셜 로그인. 매직 링크는 넣지 않는다

**이유:** D-007의 근거는 "OAuth 앱 등록 비용이 클릭 한 번 아끼는 것보다 크다"였다.
그런데 **AI 기능이 들어오면서 전제가 바뀌었다.** 이제 로그인은 편의가 아니라
요금 통제 장치다 — 누가 얼마나 썼는지 알아야 하고, 문제가 생기면 막아야 한다.
로그인이 필수가 된 이상 진입 마찰을 최소화하는 게 더 중요해졌고,
한국 사용자에게는 카카오가 이메일을 확인하러 가는 것보다 훨씬 빠르다.

매직 링크는 "메일함 열기 → 링크 찾기 → 클릭"이라 모바일에서 이탈이 크다.

**대가:** 설정이 늘었다(구글 15분, 카카오 25분). 카카오는 이메일이 안 올 수 있어서
`profiles.email` 이 비어도 동작하게 짰다 → [10-로그인-설정.md](10-로그인-설정.md)

### D-017 · 로그인은 쓰기와 AI 에만 요구한다 (2026-08-03)

**대안:** 로그인 안 하면 아무것도 못 보게 (하드 월)

**결정:** 챕터 본문·프롬프트 사전·용어 사전은 **로그인 없이 전부 읽힌다.**
프로젝트 만들기·진도 체크·AI 기능 4종만 로그인이 필요하다

**이유:** [03-화면-라우트.md](03-화면-라우트.md)에 적어둔 원칙 그대로다 —
*"친구에게 링크를 보냈을 때 로그인 벽이 먼저 뜨면 거기서 끝난다."*
이 사이트의 1차 성공 지표는 완주율인데, 하드 월은 완주 이전에 **열람조차** 막는다.

동시에 **요금이 나가는 것과 저장되는 것은 전부 로그인 뒤에 둔다.**
비로그인 AI 호출을 허용하면 주소만 알면 누구나 내 돈을 쓸 수 있다.
`api/ai.js` 가 서버에서 토큰을 검증하므로 화면을 우회해도 막힌다.

### D-018 · 어드민은 별도 사이트로 분리하지 않는다 (2026-08-03)

**대안:** 별도 저장소/배포, 또는 admin 서브도메인

**결정:** 같은 앱의 `/admin`. 화면 가드 + RLS 이중 차단

**이유:** **분리해도 더 안전해지지 않는다.** 보안은 사이트를 나누는 데서 나오는 게
아니라 DB의 RLS에서 나온다. 관리자 화면을 다른 주소에 둬도, 일반 사용자가
브라우저 콘솔에서 같은 Supabase를 직접 조회하면 그만이다 — 막는 건 RLS다.

분리하면 배포·OAuth 설정·문서가 전부 두 배가 되는데, 사용자 3명 규모에서
얻는 게 "주소가 다르다"뿐이다.

**대신 가드를 제대로 걸었다:** `is_admin` 이 아니면 컴포넌트를 렌더하지 않고(①),
`ai_usage`·`projects`·`progress` 는 RLS가 남의 행을 애초에 안 준다(②).
①만 있으면 F12로 뚫린다 — **화면 가리기는 보안이 아니다.**

**나중에 분리하고 싶어지면:** 사용자가 늘어 관리 화면이 무거워지거나,
관리자만 쓰는 기능이 많아질 때가 신호다. 그때는 서브도메인이 첫 후보다.

### D-019 · AI 사용량은 서버에 기록한다 (2026-08-03)

**바뀐 것:** localStorage 카운터 → `ai_usage` 테이블 (localStorage 는 로컬 모드 폴백으로 남김)

**이유:** 브라우저 카운터로는 **"내가 얼마나 썼나"에 답할 수 없다.**
기기를 바꾸면 0이고, 시크릿 창이면 0이고, 여러 사람 걸 합산할 수도 없다.
요금은 실제로 나가는데 숫자는 못 믿는 상태였다.

`api/ai.js` 가 OpenAI 응답을 받은 직후 사용자 토큰으로 한 줄 넣는다.
**service_role 키를 쓰지 않는다** — 사용자 본인 토큰으로 넣으므로 RLS가 그대로 적용된다.
이 저장소가 "service_role은 안 쓴다"고 말해온 걸 여기서도 지킨다.

**의도적으로 뺀 정책:** `ai_usage` 에 update/delete 정책을 만들지 않았다.
정책이 없으면 거부다 — **사용 기록은 본인도 고치거나 지울 수 없다.** 요금 근거이기 때문이다.

캐시로 재사용한 호출은 기록되지 않는다. OpenAI를 부르지 않아 요금이 안 나갔으므로,
이 표의 합이 실제 청구액에 비례한다.
