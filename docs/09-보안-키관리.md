# 보안 — 키 관리

작성 2026-08-03

이 사이트는 보안 챕터에서 "API 키를 코드에 넣지 마라"고 가르친다.
그러면 **이 저장소가 먼저 지켜야 한다.** 이 문서는 그 규칙과, 규칙을 지키는 기계 장치를 적는다.

## 한 줄 규칙

> **`VITE_` 가 붙으면 전 세계에 공개된다. 안 붙으면 서버에만 남는다.**

Vite 는 `VITE_` 로 시작하는 환경변수만 브라우저 번들에 넣어준다.
이 규칙 하나가 공개/비공개를 가른다. 다른 방어책은 전부 이것의 보조다.

## 값의 분류

| 값 | 이름 | 어디까지 나가나 | 왜 |
|---|---|---|---|
| Supabase 주소 | `VITE_SUPABASE_URL` | 브라우저 | 숨길 수 없고 숨길 필요도 없다 |
| Supabase anon key | `VITE_SUPABASE_ANON_KEY` | 브라우저 | **공개되는 게 정상.** 이 키로 뭘 할 수 있는지는 RLS 가 정한다 |
| OpenAI 키 | `OPENAI_API_KEY` | 서버만 | 새면 남이 내 돈으로 API를 쓴다 |
| Supabase service_role | — | **쓰지 않는다** | RLS 를 통째로 무시한다. 필요해지기 전엔 발급도 받지 말 것 |

### anon key 가 공개돼도 되는 이유

브라우저에 나가는 키라 숨길 방법이 없다. 숨기는 게 목적이 아니다.
**anon key 로 무엇을 할 수 있는지를 RLS 가 정한다.**
그래서 RLS 를 안 켜면 anon key = 전체 DB 공개다. → [04-데이터모델.md](04-데이터모델.md)

## 파일 구조

```
.env.example   커밋됨.   이름표만 있는 견본. 진짜 값 없음
.env.local     커밋 안 됨. 진짜 값. .gitignore 에 있음
```

시작하는 법:

```bash
cp .env.example .env.local
# .env.local 을 열어 진짜 값을 채운다
```

`.gitignore` 에 `.env`, `.env.*`, `!.env.example` 이 들어 있다.
`.env.local` 도 `.env.*` 에 걸려서 자동으로 제외된다.

## 기계 장치 — `scripts/check-env.mjs`

사람은 실수한다. 그래서 `npm run build` 가 항상 이 검사를 먼저 돌린다.
걸리면 **빌드가 멈춘다.** 세 가지를 본다.

1. **비밀 키에 `VITE_` 접두사가 붙었나** — `VITE_OPENAI_API_KEY` 같은 것
2. **소스에 진짜 키 모양의 문자열이 있나** — `sk-...`, `ghp_...`, service_role JWT
3. (`.env` 자체는 `.gitignore` 가 막는다)

직접 돌려볼 수도 있다:

```bash
npm run check-env
```

검사가 잡는지 확인하려면 일부러 위반해 보면 된다:

```bash
VITE_OPENAI_API_KEY=sk-test npm run check-env   # 빌드 중단되어야 정상
```

**오탐이 나면 검사를 끄지 말고 패턴을 좁히세요.** 끄는 순간 아무도 안 본다.

## 이미 커밋해버렸다면

가장 중요한 것부터: **코드에서 지우는 걸로는 안전해지지 않는다.**
커밋 기록에 남아 있고, GitHub 에 올렸다면 자동 스캐너가 이미 가져갔을 수 있다.

1. **그 키를 폐기하고 새로 발급받는다.** 이게 유일하게 확실한 대응이다
2. 코드에서 지우고 `.env.local` 로 옮긴다
3. 기록에 남았는지 확인한다:
   ```bash
   git log -p | grep -iE 'sk-[A-Za-z0-9]|service_role'
   ```

폐기하지 않고 기록만 지우는 건 시간 낭비다. 이미 새어 나갔다고 가정하는 쪽이 맞다.

## 배포할 때

`.env.local` 은 커밋되지 않으므로 **Vercel 은 당신의 키를 모른다.** 직접 넣어야 한다.

Vercel 프로젝트 → Settings → Environment Variables 에서
`.env.example` 에 적힌 이름 **그대로** 하나씩 추가한다.

- `VITE_` 붙은 것들 → 빌드할 때 번들에 들어감
- `OPENAI_API_KEY` → 서버리스 함수(`api/ai.js`)만 읽음

배포 후 확인:

```bash
# 번들에 키가 들어갔는지 (아무것도 안 나와야 정상)
curl -s https://<배포주소>/assets/index-*.js | grep -o 'sk-[A-Za-z0-9_-]*'
```
