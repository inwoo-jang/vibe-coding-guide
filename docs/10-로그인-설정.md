# 로그인 설정 — Supabase + 구글 + 카카오

작성 2026-08-03 · 소요 약 40분 (구글 15분, 카카오 25분)

코드는 다 돼 있습니다. **여기 있는 건 전부 웹사이트에서 클릭하는 설정**입니다.
계정이 필요해서 사람이 해야 합니다.

순서대로 하세요. 중간에 건너뛰면 뒤에서 막힙니다.

---

## 0. 지금 상태 확인

`.env.local` 에 Supabase 값이 없으면 앱은 **로컬 모드**로 뜹니다.
로그인 버튼이 없고 진도는 이 브라우저에만 저장됩니다. 그것도 정상 동작입니다.

이 문서를 끝내면 로그인이 생기고 기록이 계정에 저장됩니다.

---

## 1. Supabase 프로젝트 만들기 (10분)

1. [supabase.com](https://supabase.com) 가입 → **New project**
2. 입력
   - Name: `vibe-coding-guide`
   - Database Password: 아무거나 (**어딘가에 적어두세요.** 나중에 필요합니다)
   - Region: `Northeast Asia (Seoul)`
3. 만들어지는 데 2분쯤 걸립니다

### 키 가져오기

**Project Settings**(왼쪽 아래 톱니) → **API** 에서 두 개를 복사합니다.

| Supabase 화면의 이름 | `.env.local` 에 넣을 이름 |
|---|---|
| Project URL | `VITE_SUPABASE_URL` |
| Project API keys → `anon` `public` | `VITE_SUPABASE_ANON_KEY` |

> ⚠️ **`service_role` 키는 복사하지 마세요.** 그 키는 RLS를 통째로 무시합니다.
> 이 프로젝트는 쓰지 않습니다.

`.env.local` 이 이렇게 되면 됩니다:

```
VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...(아주 긴 문자열)
OPENAI_API_KEY=sk-proj-...
```

### 테이블 만들기

**SQL Editor** → **New query** → 이 저장소의 [`supabase/schema.sql`](../supabase/schema.sql)
**전체를 복사해서 붙여넣고 Run**.

`Success. No rows returned` 가 나오면 성공입니다.
여러 번 실행해도 안전하게 짜여 있으니, 나중에 수정하면 또 붙여넣으면 됩니다.

## 2. 구글 로그인 (15분)

### 2-1. Supabase 쪽 주소 확인

Supabase → **Authentication** → **Sign In / Providers** → **Google** 을 켭니다.
아래에 **Callback URL** 이 보입니다. 복사해두세요:

```
https://<프로젝트id>.supabase.co/auth/v1/callback
```

### 2-2. Google Cloud Console

1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 만들기
2. 왼쪽 메뉴 → **API 및 서비스** → **OAuth 동의 화면**
   - User Type: **외부**
   - 앱 이름, 지원 이메일, 개발자 연락처만 채우고 저장
   - **테스트 사용자**에 본인과 친구들 이메일을 추가합니다
     (게시하지 않으면 여기 등록된 사람만 로그인됩니다 — 친구 3명이면 충분합니다)
3. **사용자 인증 정보** → **사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
   - 유형: **웹 애플리케이션**
   - **승인된 리디렉션 URI**: 2-1에서 복사한 Callback URL 붙여넣기
4. 만들면 **클라이언트 ID** 와 **클라이언트 보안 비밀번호**가 나옵니다

### 2-3. Supabase 에 붙여넣기

Supabase → Authentication → Providers → Google 에 위 두 값을 넣고 **Save**.

## 3. 카카오 로그인 (25분)

구글보다 단계가 많습니다. 순서를 지키세요.

1. [developers.kakao.com](https://developers.kakao.com) 로그인 → **내 애플리케이션** → **애플리케이션 추가하기**
   - 앱 이름: `바이브코딩 가이드`, 회사명: 아무거나

2. **앱 설정 → 앱 키** 에서 **REST API 키** 복사
   → Supabase 의 카카오 `Client ID` 자리에 넣습니다

3. **제품 설정 → 카카오 로그인** → **활성화 설정 ON**

4. 같은 화면의 **Redirect URI** 에 2-1의 Callback URL 등록

5. **제품 설정 → 카카오 로그인 → 보안** → **Client Secret** 생성 후 **활성화 상태 ON**
   → Supabase 의 `Client Secret` 자리에 넣습니다

6. **제품 설정 → 카카오 로그인 → 동의항목**
   - **닉네임**: 필수 동의
   - **카카오계정(이메일)**: 선택 동의로 설정

7. Supabase → Authentication → Providers → **Kakao** 켜고 위 두 값 저장

> ⚠️ **이메일은 안 올 수 있습니다.** 카카오는 이메일 제공에 조건이 있고, 사용자가
> 선택 동의를 거절할 수도 있습니다. 그래서 이 프로젝트는 **이메일이 없어도 동작**하게
> 짰습니다 — `profiles.email` 이 비어도 `display_name` 으로 표시합니다.
> 이메일을 필수로 만들려면 카카오 비즈니스 채널 연결이 필요합니다.

## 4. 돌아올 주소 등록 (빼먹으면 로그인이 깨집니다)

Supabase → **Authentication** → **URL Configuration**

| 칸 | 넣을 값 |
|---|---|
| Site URL | `https://vibe-coding-guide.vercel.app` (배포 주소) |
| Redirect URLs | `http://localhost:5173/**` 와 배포 주소 `/**` 를 각각 추가 |

**로컬 주소를 안 넣으면 개발 중에 로그인이 안 됩니다.**
배포 주소를 안 넣으면 배포된 사이트에서 로그인이 안 됩니다. 둘 다 넣으세요.

## 5. Vercel 에 환경변수 넣기

`.env.local` 은 커밋되지 않으므로 Vercel은 모릅니다.

Vercel → 프로젝트 → **Settings** → **Environment Variables** 에 세 개 추가:

| Key | Value |
|---|---|
| `VITE_SUPABASE_URL` | Supabase Project URL |
| `VITE_SUPABASE_ANON_KEY` | anon public 키 |
| `OPENAI_API_KEY` | OpenAI 키 |

Environments는 Production / Preview / Development **셋 다** 체크.
저장 후 **Deployments → Redeploy** 를 눌러야 적용됩니다.

## 6. 나를 관리자로

먼저 앱에서 **한 번 로그인**해서 계정을 만듭니다. 그다음 Supabase SQL Editor 에서:

```sql
-- 내 계정 확인
select id, email, display_name from public.profiles;

-- 관리자로 (이메일이 없으면 위에서 본 id 로 지정하세요)
update public.profiles set is_admin = true where email = '내이메일@gmail.com';
-- 또는
update public.profiles set is_admin = true where id = '여기에-uuid';
```

> **왜 SQL로 해야 하나:** 앱에서는 자기 `is_admin` 을 못 바꾸게 트리거로 막아뒀습니다.
> 안 막으면 누구나 자기를 관리자로 만들 수 있습니다(권한 상승).
> 그래서 첫 관리자는 DB에서 직접 지정합니다. **의도된 불편함입니다.**

## 7. 확인 (여기까지 해야 끝난 겁니다)

- [ ] 로그아웃 상태에서 챕터 본문이 **읽힌다** (로그인 벽이 없어야 정상)
- [ ] 로그아웃 상태에서 `/projects` 에 가면 로그인 안내가 뜬다
- [ ] 구글로 로그인된다
- [ ] 카카오로 로그인된다
- [ ] 프로젝트를 만들고 챕터를 체크한다
- [ ] **시크릿 창에서 같은 계정으로 로그인하면 진도가 그대로다** ← 서버 저장 검증
- [ ] AI 기능을 한 번 쓰고 `/me` 에서 토큰 사용량이 잡힌다
- [ ] `/admin` 이 관리자에게만 열린다

### 마지막 — RLS가 진짜 막는지 (이게 제일 중요합니다)

관리자가 **아닌** 계정으로 로그인한 뒤 브라우저 콘솔에서:

```js
const { data } = await window.supabase?.from('projects').select('*')
```

콘솔에서 접근이 안 되면, 두 번째 계정으로 로그인해 `/admin` 을 열어보세요.
막히면 화면 가드는 동작하는 겁니다. DB 차원 검증은
[`supabase/schema.sql`](../supabase/schema.sql) 맨 아래 주석의 6단계를 따르세요.

**화면에 안 보이는 것과 가져갈 수 없는 것은 다릅니다.** 보안 챕터에서 가르치는
내용이니, 이 검증을 꼭 직접 해보세요.

## 안 될 때

| 증상 | 원인 |
|---|---|
| 로그인 후 `localhost` 로 튕김 | 4번 Redirect URLs 에 배포 주소를 안 넣음 |
| `redirect_uri_mismatch` | 구글/카카오에 등록한 Callback URL 오타. `https://<id>.supabase.co/auth/v1/callback` 정확히 |
| 로그인은 되는데 이름이 안 뜸 | 카카오 동의항목에서 닉네임을 필수로 안 함 |
| 로그인 후 아무것도 저장 안 됨 | `schema.sql` 을 안 돌렸거나 RLS 정책이 안 만들어짐 |
| `/admin` 이 계속 막힘 | 6번을 안 함. `profiles` 에서 `is_admin` 확인 |
| 사이트가 로컬 모드로 뜸 | `.env.local` 값이 자리표시자 그대로이거나 dev 서버를 재시작 안 함 |
