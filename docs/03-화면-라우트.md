## 프로젝트가 화면 전체를 관통한다

진도가 프로젝트에 매달리므로, **어느 프로젝트의 기록인지 화면이 항상 밝혀야 한다.**
안 그러면 사용자가 체크를 눌렀을 때 그게 어디에 남는지 모른다.

- 상단바 — 진행 중인 프로젝트 이름과 %를 항상 표시. 없으면 "프로젝트 만들기" 버튼
- `/learn` — 어느 프로젝트의 진도인지 머리말에 명시. 없으면 만들라고 안내
- `/learn/:chapterId` — 완료 체크 문구에 프로젝트 이름을 넣는다
- `/projects/:projectId` 를 열면 그 프로젝트가 "진행 중"으로 전환된다

프로젝트가 하나도 없어도 **콘텐츠는 전부 읽힌다.** 프로젝트는 기록할 때만 필요하다.

## 화면 규칙

**로그인 없이 콘텐츠 전부가 읽혀야 한다.** 로그인은 진도를 *저장*할 때만 필요하다.
친구에게 링크를 보냈을 때 로그인 벽이 먼저 뜨면 거기서 끝난다.

**`/admin`은 두 겹으로 막는다.**

1. 화면 — 관리자가 아니면 컴포넌트를 렌더하지 않는다
2. DB — RLS로 남의 행이 애초에 안 나온다

1만 하면 F12 열고 JS 몇 줄이면 뚫린다. **화면 가리기는 보안이 아니다** — 보안 챕터에서 가르치는 내용이다.

## 화면 사이의 데이터 흐름

```
chapters.js  ──▶  Home / Learn / Chapter / Prompts / Admin      (콘텐츠, 읽기 전용)
glossary.js  ──▶  Glossary

lib/projects.js (useProjects) ──▶ Layout / Home / Learn / Chapter / Projects / Project / Admin
lib/progress.js (useProgress) ──▶ Layout / Home / Learn / Chapter / Project / Admin
lib/ai.js       (useAiTask)   ──▶ Projects / Chapter / Glossary / PromptCard
                    │
                    └──▶ POST /api/ai ──▶ OpenAI     ← 키는 여기까지만
```

**화면은 `localStorage`도 `supabase`도 `openai`도 직접 부르지 않는다.** 반드시 훅을 거친다.
저장 방식이나 AI 제공자를 바꿀 때 `lib/` 아래 한 파일만 고치면 되게 하려고 만든 경계다.
이 경계를 깨지 말 것.

`progress.js` 가 `projects.js` 에 의존한다 (진도가 프로젝트에 매달리므로).
반대 방향 의존은 없다 — 프로젝트는 진도를 몰라도 된다.

## 새 화면을 추가할 때

1. [02-기능범위.md](02-기능범위.md)에 항목이 있는지 본다. 없으면 먼저 거기에 쓴다
2. 이 표에 행을 추가한다 (경로 / 로그인 필요 여부 / **한 줄짜리** 책임)
3. 책임이 한 줄로 안 써지면 화면 두 개로 쪼갤 신호다
4. `main.jsx`에 라우트를 추가하고, 필요하면 `Layout.jsx`의 `nav` 배열에 넣는다
