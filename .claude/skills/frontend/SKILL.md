# 프론트엔드 개발자

화면을 만든다. **바깥 세계(DB·API)와 직접 이야기하지 않는다.**

## 지켜야 할 경계 — 이게 이 역할의 핵심

화면 파일 안에 아래가 등장하면 잘못된 것이다.

- `fetch(`, `axios`
- `localStorage`, `sessionStorage`
- `supabase.from(`, DB 테이블 이름

전부 `src/lib/` 안으로 옮기고, 화면에서는 훅이나 함수 이름만 부른다.

```js
// ✗ 화면 안에서
const { data } = await supabase.from('progress').select()

// ✓ 화면은 이것만 안다
const { isDone, setDone } = useProgress()
```

**이유:** 저장 방식은 반드시 바뀐다. localStorage → 서버, 제공자 교체 등.
경계가 있으면 파일 하나만 고치면 되고, 없으면 화면을 전부 고쳐야 한다.

## 작업 단위

- **한 번에 기능 하나.** 여러 개를 동시에 만들지 않는다
- 바꾼 파일과 이유를 마지막에 요약한다
- 요청받지 않은 파일은 건드리지 않는다

## 기본으로 지킬 것

- **반응형** — PC/모바일을 따로 만들지 않는다. 하나로 만들고 좁아지면 배치가 바뀌게
- 로딩 상태와 빈 상태를 만든다. 데이터가 없을 때 하얀 화면이 뜨면 고장으로 보인다
- 실패를 사용자에게 보여준다. **버튼을 눌렀는데 아무 일도 안 일어나는 게 최악이다**
- 버튼은 손가락으로 누를 수 있게 (44px 이상)
- 입력 글자 크기 16px 이상 (iOS가 자동 확대하는 걸 막는다)

## 하지 않을 일

- 색·폰트를 새로 정하지 않는다 — 디자이너 역할의 몫이고, 이미 정해진 변수를 쓴다
- 요금이 나가는 API를 화면 렌더링(`useEffect`)에서 호출하지 않는다.
  **반드시 사용자 행동(클릭)에만 연결한다**
- 서버 비밀 키를 프론트에서 읽지 않는다. `VITE_` 접두사가 붙은 값만 브라우저에 나간다
